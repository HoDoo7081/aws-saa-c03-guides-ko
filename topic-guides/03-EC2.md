# 03. EC2 — 가상 서버

## 개념 이해

EC2는 컴퓨터를 빌리는 서비스입니다. 렌터카에 차종과 대여 계약이 있듯, EC2에는 **인스턴스 패밀리**와 **구매 옵션**이 있습니다. 문제의 요구 자원과 중단 허용 여부를 따로 판단하세요.

## 핵심 개념

`m5.2xlarge`에서 m은 패밀리, 5는 세대, 2xlarge는 크기입니다.

| 패밀리 | 대표 용도 |
|---|---|
| M | CPU·메모리 균형, 일반 서버 |
| T | 평소 한가하고 잠깐 부하가 커지는 버스트형 |
| C | CPU 중심 배치·인코딩·계산 |
| R / X | 메모리 중심 분석·캐시 / 대용량 인메모리 DB |
| I / D | 로컬 SSD의 높은 I/O / 대용량 로컬 HDD |
| P / G / Inf | ML 학습 / 그래픽·일부 추론 / 추론 전용 가속 |

`m7g`처럼 세대 뒤의 g는 Graviton ARM 프로세서를 뜻합니다. 애플리케이션 호환성을 확인하고 가격 대비 성능을 비교합니다. SAP HANA라는 단어만으로 무조건 X를 고르지 말고 지원 인스턴스와 용량 조건을 확인하세요.

T 계열은 CPU 크레딧을 사용합니다. Standard 모드에서 크레딧이 소진되면 기준 성능으로 제한될 수 있고, Unlimited에서는 초과 사용 요금이 생길 수 있습니다. 지속적인 고부하는 M·C 등과 비교합니다.

### 구매 옵션

| 옵션 | 선택 기준 |
|---|---|
| On-Demand | 약정 없이 단기·불규칙 사용 |
| Standard RI | 1년·3년의 예측 가능한 사용량 |
| Convertible RI | 장기 사용하되 속성 변경 유연성이 필요 |
| Compute Savings Plans | 시간당 지출 약정, 패밀리·리전과 EC2·Fargate·Lambda 간 유연성 |
| EC2 Instance Savings Plans | 특정 리전·패밀리 약정 |
| Spot | 중단·재실행 가능한 배치, 체크포인트 작업 |
| Dedicated Host | 물리 호스트 가시성·제어, 소켓·코어 기준 BYOL |
| Dedicated Instance | 다른 고객과 하드웨어 격리 필요 |

Spot은 일반적으로 2분 전 중단 알림을 제공하지만 예외가 있으므로 복구 가능한 설계가 필요합니다. 중단 불가 요구에는 부적합합니다. 기본 부하는 RI·Savings Plans, 추가 부하는 On-Demand·Spot을 조합할 수 있습니다.

**할인과 용량 보장은 다릅니다.** 리전 RI·Savings Plans만으로 특정 AZ의 용량을 확보하지 못합니다. Zonal RI 또는 On-Demand Capacity Reservation을 검토하세요.

### 배치 그룹

| 전략 | 목적 | 함정 |
|---|---|---|
| Cluster | 한 AZ 안에 가깝게 배치, 낮은 지연·높은 대역폭 | 동일 랙을 보장한다는 뜻은 아님 |
| Spread | 개별 인스턴스를 다른 하드웨어로 분산 | 리전의 랙 수준 배치는 AZ당 7개 제한 |
| Partition | 분산 시스템을 독립된 파티션에 배치 | Kafka·Hadoop·Cassandra 같은 복제형 시스템 |

### 네트워크와 시작 시 설정

- **ENI**: 사설 IP·MAC·보안 그룹을 가진 가상 NIC. 보조 ENI를 같은 AZ의 대기 인스턴스로 이동하는 장애 조치 가능. 기본 ENI는 분리 불가.
- **Elastic IP**: 리전 내 재연결 가능한 고정 퍼블릭 IPv4. 일반 자동 퍼블릭 IP는 중지 후 시작하면 바뀔 수 있음.
- **퍼블릭 IPv4는 사용 중이어도 과금 대상**. 유휴 EIP만 과금된다는 원문 설명은 오래됨.
- **User data**: 기본적으로 최초 부팅 시 초기 설정 스크립트 실행. 실행 주기는 설정에 따라 변경 가능.
- **메타데이터**: `169.254.169.254`. IMDSv2는 세션 토큰 사용, SSRF 위험 완화.
- **최대 절전(Hibernate)**: RAM을 암호화된 EBS 루트 볼륨에 저장. 지원 인스턴스·OS·용량 조건 확인.

## 문제 유형

1. 실패한 이미지 처리 작업을 다시 실행할 수 있고 최저 비용 요구 → Spot 검토.
2. 소켓 단위 기존 라이선스를 AWS에서 사용 → Dedicated Host.
3. 같은 AZ에서 기존 사설 IP로 대기 서버가 응답해야 함 → 이동 가능한 보조 ENI 검토.
4. 유지보수 후 퍼블릭 IP가 변경됨 → EIP 또는 로드 밸런서·DNS 구조 검토.
5. HPC 노드 간 통신 지연 최소화 → Cluster 배치 그룹.

## 빠른 복습표

| 단서 | 답 후보 |
|---|---|
| CPU 크레딧 소진 | M·C로 변경 또는 Unlimited 비용 검토 |
| 할인과 별도로 용량 확보 | Capacity Reservation·Zonal RI |
| 중단 가능한 배치 | Spot |
| 같은 사설 IP 장애 조치 | 보조 ENI, 같은 AZ |
| 물리 서버 라이선스·소켓 | Dedicated Host |
| 메타데이터 SSRF 보호 | IMDSv2 강제 |
| RAM 상태 보존 | Hibernate |
